L.A.R.R.I. 🦞 Cookbook (As of Sep '26)

Commands that work, and what they land on.
Every command below was run before it was written down.
home· guide· start here· chat· coding· reasoning· documents· vision· cheapest· in the background· what it cannot do

Prices and hardware below are what LARRI actually selected on a real market, and they will not be what you see: the market moves hourly. They are here to set expectations, not promises.

Add --dry-run to any command to see the sizing, the hardware, the wait and the bill without renting anything. Do that first, every time.

A 2× or 4× is that many cards in one host. When a model is too big for one card, LARRI splits it across several by default and picks whichever fits most cheaply — often an older card doubled up beats one large one. --max-gpus 1 keeps it to a single card.

⚠ These commands spend money. A rig bills from the moment it is created — including while it downloads. Ctrl-C tears it down, and larri down ends one started with -d; larri orphans catches anything a crash left behind.

Start here

The cheapest thing that proves the whole path works.

Smoke test — a few cents

larri up --model Qwen/Qwen2.5-1.5B-Instruct

Lands on RTX 3060 12GB · ~$0.04/hr · needs 4.6 GB · ready in ~4 min. This is the model LARRI's own end-to-end tests use, so a failure here is the host or LARRI, never the model.

General chat & knowledge

Everyday assistant work: questions, drafting, summarising.

Qwen3 8B — the default recommendation

larri up --model Qwen/Qwen3-8B

Lands on 2× RTX 3060 24GB · ~$0.10/hr · needs 19.6 GB. Text-only, tool-calling works out of the box.

Qwen3 14B — noticeably better, roughly double

larri up --model Qwen/Qwen3-14B

Needs ~35 GB, so it lands on 4× RTX 3060 48GB · ~$0.18/hr.

Llama models on Hugging Face are gated — you must accept the licence on the model page and use an HF_TOKEN that has been granted access, or the download 403s after you have already paid for the rig.

Coding

Autocomplete, refactoring, and agent loops in your editor.

Qwen2.5-Coder 7B — fits a cheap card

larri up --model Qwen/Qwen2.5-Coder-7B-Instruct

Lands on 2× RTX 3060 24GB · ~$0.10/hr · needs 17.5 GB.

Qwen2.5-Coder 32B — the one worth renting a real GPU for

larri up --model Qwen/Qwen2.5-Coder-32B-Instruct --context 32768

Lands on 4× RTX 2080 Ti 88GB · ~$0.39/hr · needs 82.7 GB · ready in ~13 min. 61 GB of weights, so LARRI rents an 86 GB disk to hold them. Try --dry-run first — this is where the download dominates the bill.

For agent modes (Continue.dev, AnythingLLM agents, Cline) the model must emit tool calls and vLLM must be told how to parse them. LARRI derives the parser from the model family automatically; override with --tool-parser if a client reports malformed tool calls.

Reasoning

Maths, multi-step logic, anything where the model should think before answering.

DeepSeek-R1 distilled into Qwen 14B

larri up --model deepseek-ai/DeepSeek-R1-Distill-Qwen-14B

Lands on 4× RTX 3060 48GB · ~$0.18/hr · needs 34.6 GB. Reasoning models emit long chains of thought, so raise your client's max-tokens or answers will be cut off mid-thought.

Documents & long context

Summarising, extraction, and question-answering over long inputs.

A large context window, costed honestly

larri up --model Qwen/Qwen3-8B --context 65536

Context is not free: the KV cache grows linearly with it, and LARRI sizes for it before renting. Compare --context 8192 against --context 65536 with --dry-run and watch the required VRAM — and the GPU it forces you onto — move.

LARRI sizes for one concurrent sequence. Several clients hitting the same rig at once multiply the KV cache and can exhaust VRAM. It warns about this at every bring-up.

Images as input

Reading screenshots, diagrams, scanned documents.

Qwen2.5-VL 7B

larri up --model Qwen/Qwen2.5-VL-7B-Instruct

Lands on 2× RTX 3060 24GB · ~$0.10/hr · needs 19.0 GB. Send images as ordinary OpenAI image_url content parts.

Vision models need memory for an image encoder that LARRI's sizing does not yet count. Give them headroom — prefer a card comfortably above the figure LARRI reports rather than one that only just clears it.

The cheapest possible rig

When you want a working endpoint for pennies and do not need speed.

Quantised weights, llama.cpp, old hardware

larri up --model unsloth/Qwen3-8B-GGUF --runtime llamacpp

Lands on RTX 3060 12GB · ~$0.04/hr · 4.7 GB of weights. llama.cpp runs on cards vLLM refuses, and its image is a fraction of vLLM's 8.6 GB. LARRI defaults GGUF engines to Q4_K_M — roughly a quarter the size of full precision — and names smaller quantisations in the repo if you want to go further. To pick one yourself, name it with --quantization or name the file: unsloth/Qwen3-8B-GGUF/Qwen3-8B-Q8_0.gguf.

Let LARRI find a smaller version of what you asked for

larri up --model Qwen/Qwen3-14B --dry-run

Every bring-up looks for a quantised publication of the same model and reports what it would save — usually 3× less to download and a much cheaper GPU. It suggests; it never substitutes, because a quantised model is not the same model.

In the background & from an agent

Rigs that outlive the command that started them.

Get your terminal back

larri up -d --runtime llamacpp --model Qwen/Qwen2.5-1.5B-Instruct-GGUF --quantization Q4_K_M --gpu "RTX A4000" --verified-only --min-netspeed 1000

Lands on RTX A4000 15GB · ~$0.10/hr · 1.0 GB of weights · ready in 3–7 min. It asks, as larri up always does, then returns at READY and leaves a larri process holding the tunnel, with the idle timeout and budget still watching. A verified card on a fast link: without those filters, the same model on vLLM landed on a $0.038/hr host that was still pulling the image after 25 minutes.

Follow it, then end it

larri logs -f 01m2h2 # bring-up to READY, then supervision — a prefix of the rig id will do larri down 01M2H2AP7E…

logs -f keeps going through the teardown — the idle warning, "confirmed absent", DESTROYED — and exits with the process that held the rig.

From an agent that runs shell commands

larri up -d --yes --json --runtime llamacpp --model Qwen/Qwen2.5-1.5B-Instruct-GGUF --quantization Q4_K_M --max-price 0.40 --gpu "RTX A4000" --min-netspeed 1000 --verified-only

One JSON object on stdout — rig, endpoint, model, price_hr, pid, log — or "ok":false with the error. Without a terminal, -d refuses to rent unless --yes is there. A client key made for the first time comes back once, as "key", and nowhere else.

After the holding process died

larri resume -d --json 01M2H0GKP6…

Reconnected in 20 s without restarting the model, supervised again, on the same endpoint and the same client keys. Vast.ai only: RunPod cannot add a key to a running pod.

What LARRI cannot do

Worth stating plainly, so you do not spend money finding out.

Task Status
Image generation
Stable Diffusion, FLUX, ComfyUI		 Not supported. All three runtimes — vLLM, llama.cpp, Ollama — are LLM servers speaking OpenAI /v1/chat/completions. A diffusion pipeline needs a different runtime and a different API surface. Nothing in the cookbook will generate an image.
Audio / speech
Whisper, TTS		 Not supported, for the same reason.
Embeddings Untested. vLLM can serve embedding models, but LARRI's readiness check demands a chat completion, so an embedding-only model will never be declared ready.
Fine-tuning / training Out of scope. LARRI rents a GPU to serve a model.

If image generation is what you want, rent through the provider's own console and use their ComfyUI template — LARRI would only be in the way.

Flags worth knowing

Flag Why
--dry-run Sizing, hardware, wait and bill — without renting. Use it first.
--session 8 Optimise the choice for a long session: the download amortises and the hourly rate starts to dominate.
--max-price 0.50 Hard ceiling per hour.
--gpu "RTX 3090" Restrict to hardware you trust.
--max-gpus 1 Keep the model on one card instead of splitting it across several.
--verified-only Only hosts the provider has verified. Costs more, fails less.
--idle-timeout 15m Destroy sooner when nobody is using it.
--port 8080 When something else already holds 8000.
-d Return once the rig is serving; a larri process holds it. --yes --json for scripts and agents.
--new-key A client key for this rig only, instead of the one every rig accepts.
--context 32768 Bigger window, bigger KV cache, bigger GPU.
