Quick start

Four commands, about five cents. Every section below expands on one of them.

export VASTAI_API_KEY=... # a funded provider account export HF_TOKEN=... # for gated models export LARRI_LABEL_KEY=$(bin/larri label-key) # optional: seal what the provider sees bin/larri up --model Qwen/Qwen2.5-1.5B-Instruct --dry-run # costs nothing bin/larri up --model Qwen/Qwen2.5-1.5B-Instruct # rents, serves, holds the tunnel

The last command prints the three values every client needs, and holds the rig until you stop it:

✓ rig 01M0ZXE8… READY http://127.0.0.1:8000/v1 model: qwen2.5-1.5b-instruct key: fKLtIo4OscEe1W7a0TYJasIlaH6Q0tc530Vi-n5n7Ow holding the tunnel — Ctrl-C to tear down and stop paying

Point any OpenAI-compatible client at http://127.0.0.1:8000/v1 with that key and model name. Ctrl-C destroys the rig and stops the bill.

Two habits worth forming immediately: run --dry-run first, every time — it shows the hardware, the wait and the bill without renting anything. And copy the key when it appears: it is minted per bring-up and printed once.

That is the whole product. The rest of this page is detail: setup · first rig · wiring a client · stopping · daily commands · failures

Setup, in detail

The three environment variables above, and what each one actually buys you. Once per machine; only the first is mandatory.

  1. A provider API key required

    You need a funded account with at least one provider. LARRI never handles the money — it spends what is already there.

    export VASTAI_API_KEY=... # console.vast.ai → Account → API Keys export RUNPOD_API_KEY=... # runpod.io → Settings → API Keys

    With both set, LARRI uses whichever your configuration lists first. Name one explicitly with --provider vastai or --provider runpod.

  2. A Hugging Face token recommended

    Needed for gated models — Llama and Gemma among them — and harmless otherwise.

    export HF_TOKEN=... # huggingface.co/settings/tokens (read scope)
    Set it before you need it. A gated repository fails after the rig is already rented and paid for — the download is the first thing that discovers the token is missing.

  3. A label key optional

    LARRI stamps every rented resource so an abandoned one can be found and destroyed later. This seals the descriptive part of that stamp — model, runtime, price — so the provider and host operator cannot read it.

    export LARRI_LABEL_KEY=$(bin/larri label-key)

    32 random bytes, base64. The command prints the key on stdout and its explanation on stderr, so that line captures exactly the key.

    Keep it. Without a key, rigs are still labelled and still destroyable — the rig ID is always in the clear, so orphan detection works either way. But lose a key you have been using and larri orphans can no longer say what a surviving rig was for. LARRI will never generate one silently, because a key you do not know exists is a key you cannot back up.

  4. Make them permanent

    All three are read from the environment on every run. LARRI writes none of them to disk.

    # ~/.bashrc or ~/.zshrc export VASTAI_API_KEY=... export HF_TOKEN=... export LARRI_LABEL_KEY=...

    Prefer a file? Use LARRI_LABEL_KEY_FILE=~/.config/larri/label.key instead.

The labels line tells you whether the key was found. --dry-run stops there — nothing has been rented.

Your first rig

bin/larri up --model Qwen/Qwen2.5-1.5B-Instruct

It asks once, before it spends:

rent RTX 3060 12GB at $0.047/hr? [y/N] y

Then it rents the machine, installs a throwaway SSH key, pins the host key, checks the host can actually reach Hugging Face, launches the runtime, and waits for a real completion to come back — not a health check, an actual generated token.

✓ rig 01M0ZXE8… READY http://127.0.0.1:8000/v1 model: qwen2.5-1.5b-instruct vastai RTX 3060 at $0.047/hr key: fKLtIo4OscEe1W7a0TYJasIlaH6Q0tc530Vi-n5n7Ow policy: idle 30m0s → destroy · no budget ceiling holding the tunnel — Ctrl-C to tear down and stop paying
Copy the key now. It is minted per bring-up and printed once; larri status does not repeat it. Leave this terminal open — it is holding the tunnel and supervising the rig.

Wire a client

Three values, from the lines above. The base URL never changes, whichever provider or GPU won the ranking — that is what the tunnel is for.

Running the client in Docker? Give it --network=host. The endpoint binds loopback only, so host.docker.internal cannot reach it — and that bind is what stops any page in your browser from spending your money.

Stop paying

Ctrl-C in the terminal holding the rig, or from anywhere:

bin/larri down

It destroys the rig, re-queries the provider to confirm it is actually gone, and reports the total. A 200 from a delete endpoint is a claim; absence from the inventory is evidence.

If a LARRI process ever dies unexpectedly

bin/larri orphans bin/larri orphans --destroy
A rented container cannot end its own billing — measured, not assumed: the capability to reboot itself is not granted to it. So if the local process dies, larri orphans is the only thing that stops an abandoned rig costing money. Run it if a machine ever crashes on you.

By default an idle rig destroys itself after 30 minutes and says so at bring-up. Change it with --idle-timeout 15m.

FlagWhy

When it fails

The cheap end of the market is rough. LARRI checks what it can before spending and falls back when a host fails anyway; expect an attempt or two to be discarded. That is the market, not a malfunction.

What you seeWhat it means
host has no working internet The machine cannot reach Hugging Face or Docker Hub. It is a bad rental; LARRI abandons it in about 20 seconds and takes the next offer.
host cannot reach huggingface.co
…retry with --hf-endpoint		 The machine is online but its region cannot route to Hugging Face. It names a mirror it can reach. Opt-in: weights would then come from a third party.
provider gave up on the instance The provider's own container runtime failed — often GPUs that could not be attached. Nothing you can fix; LARRI moves on immediately.
verification-withdrawn Not an error. The provider granted this host verification and later took it back, so LARRI skips it. --allow-deverified to include them anyway.
local port 8000 is already in use Something else holds the port. Use --port 8080. Checked before renting, so it costs nothing.
bring-up hit the … ceiling A slow host ran past the attempt limit. Raise it with --deadline.
400 "auto" tool choice requires… Agent mode needs a tool-call parser. LARRI derives one from the model; if a client still reports malformed calls, set --tool-parser explicitly.
⚠ The host can read your prompts. Inference happens in plaintext on a stranger's GPU, and whoever owns that machine has root. The tunnel protects your traffic on the way there; it cannot protect it from the far end. Run larri privacy for the whole explanation. Send a rented GPU nothing you could not afford to publish.
